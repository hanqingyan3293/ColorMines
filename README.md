# Color Mines 颜色扫雷

一个规则简单的扫雷变体：**每种颜色恰好一个雷**，每行每列的数字是该行/列雷的总数。
纯逻辑即可通关，不需要猜。桌面端（Tauri）与 Web/PWA 共用同一份核心实现。

## 规则

- 棋盘每格有一种颜色；**每种颜色恰好有一个雷**
- 每行、每列旁边的数字 = 该行/列雷的总数
- 颜色**全程可见**，需要找出的是"哪个格子是雷"
- **左键**循环标记：空白 → `?` → `⚑` → 空白；**每种颜色最多一面旗**（只标记，不会踩雷）
- **右键排雷**（挖开格子）是**可选的风险操作**——挖到雷就输，但完全不挖也能赢
- 按住左/右键拖动可连续标记 / 连续排雷
- 胜利 = 每种颜色的旗都插在它真正的雷上

产物体积：web 约 45 kB JS（gzip 15 kB）+ worker + CSS；桌面 exe 3.4 MB、安装包 1.1 MB。

## 界面

四个主要视图，从导航栏或主页卡片进入：

- **主页**：四张入口卡片（开始游戏 / 游戏设置 / 历史 / 导入导出）+ 当前配置 + 规则速览
- **开始游戏**：只有棋盘与游戏相关操作（提示、直接提示、复盘、保存地图、返回菜单），设置在对局中不可见
- **游戏设置**：尺寸、颜色数、行列分组、生成超时、历史条数、语言、调试模式、数据位置

点击「复盘」后棋盘移到左侧、推理链在右侧，同一屏内不翻页。

## 操作

| 操作 | 效果 |
|---|---|
| 左键单击 | 标记循环：空白 → `?` → `⚑` → 空白（只做标记，不会踩雷） |
| 右键单击 | 排雷（挖开），挖到雷即失败 |
| 按住左键拖动 | 连续标记扫过的格子 |
| 按住右键拖动 | 连续排雷 |
| 方向键 / F | 键盘移动与标记 |
| Ctrl/⌘ + N | 新对局 |

## 提示

每局有次数上限（简单配置 5 次，分组模式与大盘 3 次）。提示会说出**颜色**和它所在的**行/列带**，
但不点名具体格子；每次提示沿推导链往下走，不会重复消耗次数。另有「直接提示」直接给出答案，
用过则本局不计分。

## 数据与存储

用户数据保存在统一数据文件夹中（桌面端默认为系统应用数据目录下的 `app.colormines.desktop`）：

```
data/
├── settings.json
├── history.json (+ .bak / .bad)
├── maps/     保存的地图，每张一个 UUID 命名的 JSON
├── logs/     app.log（滚动保留 200 行）
└── backups/  最近 10 份备份

写入采用「临时文件 → 校验 → 替换」，损坏的设置有 `.bad` 备份、损坏的历史会尝试 `.bak`（恢复前逐条校验）。

设置页可查看每类数据的完整路径，并用系统文件夹选择器更改数据位置、或迁移现有数据过去。

桌面端文件读写由 Rust 原生命令实现（`tauri-plugin-fs` 在此环境下会拒绝所有路径，已弃用）。

## 难度

档位不是拍脑袋定的，是量出来的（`npm run mass`，每档 1500 次尝试预算）：

| 档位 | 尺寸 | 雷 | 成功率 | p50 | p95 | 推理步数 |
|---|---|---|---|---|---|---|
| 入门 | 6×6 | 4 | 100% | 0ms | 1ms | 25 |
| 简单 | 8×8 | 6 | 100% | 1ms | 2ms | 45 |
| 普通 | 10×10 | 8 | 100% | 1ms | 5ms | 71 |
| 困难 | 12×12 | 10 | 100% | 12ms | 46ms | 113 |
| 专家 | 12×12 | 12 | 100% | 34ms | 142ms | 115 |
| 极限 | 16×16 | 8 | 100% | 9ms | 39ms | 150 |

每一局都**保证唯一解且纯逻辑可推**。"推理步数"是逻辑求解器需要的推导步数，
是这里唯一可量化的难度代理指标。

自定义参数完全开放，但会用 `estimateFeasibility()` 预警：可行域大致是
**雷数 × 格数 ≲ 2000**。超出后生成会变慢甚至失败，此时 UI 会给出具体建议。

## 结构

```
src/
  core/     游戏核心（唯一一份，两端共用）
    board.ts          棋盘模型与不变式
    solver-exact.ts   精确求解器（证明唯一解）
    solver-logical.ts 逻辑求解器（证明可纯推理完成）
    generator.ts      生成 + 验证
    session.ts        对局规则（翻开/标记/胜负）
    hint.ts           提示与复盘
    scores.ts         最佳成绩
    tiers.ts          难度档位与可行性估计
  ui/        渲染（vanilla TS）
  i18n/      中英双语目录
  cli/       量产工具
src-tauri/  Tauri 桌面壳（Rust 仅 11 行）
tests/      核心测试
```

**核心只有一份**：桌面端加载的是与浏览器完全相同的 bundle，Rust 侧只有一个空壳。
上一版项目最大的代价就是两端两套实现，这次从结构上杜绝了。

## 保证从哪来

棋盘生成是"采样—验证—拒绝"：随机布局 + 随机布雷，然后用两个求解器检验，
不合格就重来。关键测量结果是——**"逻辑停滞"在所有配置中一次都没出现**：

> 只要棋盘唯一，它必然能被纯推理解出。

所以实际只需要保证唯一性，可解性是白送的。唯一性的敌人是"矩形交换退化"
（两种颜色可在 (r1,c1)(r2,c2) 与 (r1,c2)(r2,c1) 之间互换而行列总数不变）。
